# dsh-claude-skin（desktop 分支）

把 Claude 皮肤装回来 —— 不需要皮肤中心。

**这个分支是桌面端适配版**。`master` 是 web 端主线；本分支在它之上加了桌面端
（`dsh-app://app`）的兜底，web 端行为零变化。

## 桌面端的问题与本分支的做法

桌面宿主会渲染结构化注入行（样式表能进 `<head>`），但**丢掉了全部 `tapIndex`
变换** —— 皮肤的作用域属性 `data-dsh-skin` 永远不会被盖到 `<html>` 上。样式表
里每条选择器都挂在 `html[data-dsh-skin="claude"]` 底下，属性不在，一条都匹配
不上，看起来就是"皮肤完全没生效"。

本分支让客户端补上宿主漏掉的那一步：

1. 客户端启动时检查 `<html>` 上有没有 `data-dsh-skin` 属性（**只看属性**，
   不看 head 文本里有没有这个字符串——那个来自样式表内容，必然为真）。
2. 属性在（web 端）：什么都不做。不发请求、不写 DOM。
3. 属性不在（桌面端）：从新路由 `GET /api/dsh-claude-skin/stylesheet`
   拉取作用域化后的样式表文本，设置属性，并给样式表一个稳定 id
   （替换宿主注入的那份裸 `<style>`，不是追加——追加会翻倍）。

服务端同时新增了这条 stylesheet 路由（`asset` 路由有目录穿越校验，拿不到
`skin.css`），并抽出 `injectableStylesheet()` 共用安全检查。

已实测：web 场景客户端不动手；桌面场景属性补上、样式替换不翻倍、三次重复
调用仍是一份。单测 26 项全过（含一条「路由文本与注入行逐字节一致」的契约）。

## 它是什么

（与 master 相同的部分）

1. **自动装好皮肤**：首次加载时把仓库里的 `claude/` 拷进 `$DSH_HOME/skins/claude`，
   只补缺、不覆盖。
2. **注入皮肤样式表**：读皮肤的两份样式表，过作用域改写，通过官方
   `webserver/index-inject` 索引注入表塞进页面。
3. **戳 `<html>` 属性**：通过 `webServer.tapIndex`（桌面端这步由客户端兜底）。
4. **送资产**：皮肤的字体与图片走插件路由。
5. **管皮肤**：列出、切换。

## 设置

设置 → **Claude-X**，一个页面管三件事：皮肤、名字/副标题/头像、以及
「侧栏底部那行」的开关。数据存在浏览器本地，不上传。

## 安装（桌面端）

```powershell
# 在 desktop profile 目录
pnpm install   # 指向本仓库 link:…/plugins/skin
```

重启 DSH 桌面应用（客户端插件不支持热替换）。

**web 端请用 `master` 分支**——本分支在 web 上虽然零副作用，但没有理由不用主线。

## 已知限制

- **皮肤切换仍要刷新页面**（两条路径都一样：样式在文档渲染时确定）。
- **`tapIndex` 在桌面端失效是 DSH 宿主的缺陷**，影响任何使用该扩展点的插件。
  本分支是绕过，不是修复；宿主修好后本分支的兜底会自动变成空操作
  （属性已在，客户端直接退出）。
- 不做白名单过滤（同 master）：只跑自己写得明白的皮肤。
