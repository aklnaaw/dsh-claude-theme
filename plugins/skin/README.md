# dsh-claude-skin（桌面端分支）

把 Claude 皮肤装回来 —— 不需要皮肤中心。

**这个分支只做桌面端**（`dsh-app://app`，DeepSeek Harness 桌面应用）。
web 端请用 `master` 分支，两边各自维护、互不合并。

## 为什么有这个分支

桌面端有个宿主缺陷：它渲染结构化注入行（样式表能进 `<head>`），但丢掉全部
`tapIndex` 变换 —— 皮肤的 `data-dsh-skin` 属性永远不会被盖到 `<html>` 上。
样式表里每条选择器都挂在 `html[data-dsh-skin="claude"]` 底下，属性不在，
一条都匹配不上，看起来就是"皮肤完全没生效"。

这个分支让客户端补上宿主漏掉的那一步：启动时检查 `<html>` 属性（只看属性，
不看 head 文本——那个字符串来自样式表内容，必然为真），不在就从
`GET /api/dsh-claude-skin/stylesheet` 拉样式表、设属性、把宿主那份裸
`<style>` 换成带稳定 id 的（替换不是追加，追加会翻倍）。

**坦白说**：我平时不怎么用桌面端，这个分支是在桌面端上一次性调通的，
之后没怎么跑过。基本功能（样式生效、皮肤切换）实测过，但不保证每个版本
的桌面宿主都好使——坏了的话先看控制台有没有报错，再回 master。

## 它是什么

1. **自动装好皮肤**：首次加载时把仓库里的 `claude/` 拷进 `$DSH_HOME/skins/claude`，
   只补缺、不覆盖。
2. **注入皮肤样式表**：过作用域改写后通过官方索引注入表塞进页面。
3. **戳 `<html>` 属性**：服务端 `tapIndex`（桌面端失效）+ 客户端兜底（本分支独有）。
4. **送资产**：皮肤的字体与图片走插件路由。
5. **管皮肤**：列出、切换。

## 设置

设置 → **Claude-X**：皮肤、名字/副标题/头像、侧栏底部那行的开关。
数据存浏览器本地，不上传。

## 安装（桌面端 profile）

```powershell
pnpm install   # profile 里 link: 指向本仓库 plugins/skin
```

重启 DSH 桌面应用生效。

## 已知限制

- **皮肤切换要刷新页面**（桌面端也一样）。
- **`tapIndex` 失效是 DSH 桌面宿主的缺陷**，本分支是绕过不是修复；
  哪天宿主修好了，这里的兜底会自动变成空操作。
- 不做白名单过滤：只跑自己写得明白的皮肤。
